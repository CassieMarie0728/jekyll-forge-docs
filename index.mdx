Jekyll Forge is a writing workspace for Jekyll blogs stored on GitHub. You edit Markdown and front matter, keep drafts in Forge, review repository changes, and publish through GitHub. AI is optional. You remain the author, editor, and person who has to live with the headline.

## Pick your route

**Writing a blog:** start with the quickstart, then editing, recovery, publishing, and scheduling.

**Fixing something:** use [Troubleshooting](/troubleshooting/common-problems). Preserve your draft before attempting the ritual known as “clear everything and refresh.”

**Operating the app:** read deployment, configuration, backups, and security. The hosted browser app runs without your laptop staying on.

**Changing the code:** read architecture and the source-derived procedure reference. Those procedures are an internal contract, not a promised stable public API.

## Three receipts you should recognize

| Message or action | What it establishes |
| --- | --- |
| Browser recovery saved | A copy exists in this browser profile |
| Save succeeded | A draft exists in Forge's database |
| Publish succeeded | A GitHub write completed; check the website build separately |

## Honest boundaries

Provider billing belongs to the provider account. Free hosting has quotas. Social publishing and physical-device mobile behavior have acceptance gaps. A health check is not a security audit, and a successful deployment is not proof that every button works.

Read the [verification ledger](/reference/current-state) before treating a feature as production-proven. No imaginary superpowers. We have enough actual ones to document.
