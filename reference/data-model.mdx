D1 stores the application's account, workspace, draft, integration, scheduling, and analytics state. Repository files remain in GitHub. Browser recovery remains in the browser.

## Active tables

- `users`
- `mobileDeviceTokens`
- `mobileAuthCodes`
- `sites`
- `posts`
- `snapshots`
- `assets`
- `aiSettings`
- `userAiProviders`
- `scheduledPosts`
- `reusableBlocks`
- `frontMatterTemplates`
- `repurposedContent`
- `socialMediaAccounts`
- `scheduledSocialPosts`
- `contentAnalytics`
- `contentVariations`
- `abTestResults`
- `abTestSummary`
- `rateWindows`
- `operatorNotifications`

## Schema authority

The linked Drizzle schema defines fields, types, defaults, and indexes. The SQLite SQL files in `drizzle/d1` define migration history. There are four migration files at this revision, numbered 0000 through 0003; do not reuse the older guide's initial three-migration count.

User records and integration records contain sensitive data. Keep database exports private. The schema alone does not establish retention periods, backup frequency, or operational access controls; those policies are operator responsibilities.

## Restore and migration boundaries

Test restores against an isolated database. A source-code rollback is not a schema rollback. Preserve the database, secrets required to decrypt AI keys, and GitHub repository history as separate recovery inputs.
