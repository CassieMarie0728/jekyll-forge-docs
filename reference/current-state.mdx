## Labels used in this manual

**Source-reviewed:** behavior is supported by the linked implementation. It may not have been exercised against a live upstream service.

**Tested:** a named test or walkthrough has recorded results. Check whether upstream calls were mocked and whether the evidence predates the current deployment.

**Unknown / not verified:** the evidence does not support a stronger claim. This is a useful answer, not a failure of enthusiasm.

**Not applicable:** a feature or claim does not apply to this runtime—for example, keeping your laptop on to serve the hosted app.

## Known limitations

- Existing build output includes large JavaScript chunks; measured performance work remains.
- Two historical Pages workflows remain in the app repository. The new landing layout supports both artifact shapes; consolidating workflows remains separate maintenance.
- Jekyll custom themes may require manual dependencies and deployment changes.
- Browser recovery is local to one browser profile.
- Provider quotas and billing can change independently of the app catalog.
- Historical audit files can describe old failures that later follow-up sections resolved. Read their dates and follow-ups.

## Updating the evidence

When code changes, update the source revision, affected guides, generated procedure catalog, and this ledger. Record actual results. Do not promote “has a test file” into “all tests passed.”
